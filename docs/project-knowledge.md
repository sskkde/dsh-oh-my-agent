# 项目知识组织规范（project knowledge layout）

本规范约定一个仓库如何安置四类知识：**行动规则**、**现行事实**、**决策因果**、**任务工件**。
每类知识只有一个权威正文；写进哪一层由"读者是谁、什么时候读、谁来更新"决定，不由"内容长短"决定。

`@dsh-external/dsh-oh-my-agent` 的规则引擎按本规范加载 `AGENTS.md`（加载契约见
[subsystems/rule-loading.md](./subsystems/rule-loading.md)）；本插件仓库自身也按本规范组织——本文件即示范，不强制把整套树部署到用户项目。

## 四层职责

| 层 | 装什么 | 读者 / 何时读 | 更新者 | 是否派生 | 版本管理 |
| --- | --- | --- | --- | --- | --- |
| `AGENTS.md`（根 + 复杂子目录） | 简短、稳定的**行动规则**：硬约束、关键验证命令、往 docs/notes 的导航 | agent 会话开始（根级常设）与读取文件时（祖先作用域）自动命中 | 维护者随行为变更手工更新 | 否（权威正文） | git 纳管 |
| `docs/`（architecture / subsystems / cookbook，按需建） | **现行事实**：架构、子系统契约、操作手册 | agent 与人按需 `read`（AGENTS 只放指针） | 随代码变更同步更新 | 否（权威正文） | git 纳管 |
| `docs/postmortems/`（可选） | **历史复盘**：文首明确标注"历史，不是现行规则" | 排查同类问题时按需 `read` | 写后不改写旧篇，新事实开新篇 | 否 | git 纳管 |
| `.agent-notes/`（默认；已有旧路径见下节） | **决策因果**：背景、选择、被否决方案、成立条件、证据、替代方案 | agent 按需 `read`；`learnings.md` 是一行结论 + 指针的热索引 | 决策发生时追加 | `notes/<topic>.md` 是唯一正文；learnings 行是索引，不是第二权威 | git 纳管或本地，由项目自定 |
| `.omo/` | **按类别管理的任务状态与派生物**：批准的 plans、人工 memory、Boulder 状态、验证证据，以及 compiled rules / 索引 | 人与插件经显式工具按需读写；编译或索引产物可由来源重建 | 维护者/用户维护权威状态；插件更新运行状态；编译器重建派生产物 | **不全是派生物**：批准计划、人工记忆、Boulder 状态与验证证据不得按缓存整体删除；compiled rules / 索引才可重建 | 按类别版本管理：权威状态与验收证据保留并按项目策略纳管；可重建产物可不入库/随时重建 |

## 单权威来源

- 行动规则改 `AGENTS.md`/规则文件；现状改 `docs/`；因果写 `.agent-notes/notes/`。
- 同一事实出现在两层时，另一层只放一行指针，不复述正文——双权威必然漂移。
- `.omo/` 是位置约定，不是生命周期分类：批准的 plans、人工 memory、Boulder 工作状态/经验记录、验证证据均可能是唯一权威记录或审计依据，不能因为位于 `.omo/` 就整体删除或当作缓存。memory 中明确标记为摘要的内容应保留其来源指针；旧 memory 不自动转成派生摘要、不自动重分类或迁移，以兼容既有记录。版本管理按类别决定：权威状态和证据应保留并按项目策略纳管，`compiled rules`、搜索/导航索引等明确可再生成产物可重建。memory 摘要不能替代原始决策正文，过期摘要需核对来源后更新。

## AGENTS.md 写法

- **根 AGENTS**：简短稳定——每个会话都该成立的约束、关键验证命令（与 package.json/脚本一致）、导航链接。
- **局部 AGENTS**（子目录）：只写该层特有规则与契约链接，不重复根级内容；只适用其所在目录子树
  （规则引擎按祖先路径命中，见 [subsystems/rule-loading.md](./subsystems/rule-loading.md)）。
- **不承载详细架构正文**——那是 `docs/` 的事，AGENTS 放链接即可。
- 小项目按需省略层次：没有子目录规则就不建局部 AGENTS，没有独立子系统就不建 `docs/subsystems/`。

## docs：现行与复盘分开

- `docs/` 只描述**现在是什么**；写"我们曾决定/曾踩坑"的内容进 `docs/postmortems/`（或 notes）。
- 历史结论不得当作现行规则引用——规则以 `AGENTS.md`/规则文件为准。

## notes 写入判据

只写"**遗忘会误导后续工作**的非平凡变更"：背景、被采纳的方案、**被否决的方案及原因**、成立条件、证据出处、替代方案。
琐碎过程、能从 git 历史或代码直接看出的内容不写。没有固定跨项目字数硬门——判据是"遗忘是否误导"，不是长度。

## 旧路径兼容

已有 `.agents/notes/` 等布局**保持可用**：通过 AGENTS 里的显式引用读取。插件不承诺自动发现这些路径，
也不会自动迁移、改名或改写旧记录。新项目默认 `.agent-notes/`。

## 非目标（诚实边界）

- 不自动整理、重分类既有文档；本规范不追溯旧记录。
- 没有"零维护"承诺：文档随代码变更由维护者更新。
- 本规范是组织约定，不是机器可执行的硬约束；规则注入是提示上下文，不是写入前强制安全门。
- 自动规则注入仅限成功 `read` / `edit` 的 file 通道、会话开始时的根级常设规则，以及 `omo_agents brief` / `delegate_as` 按显式 `files` 目标组装的上下文；其他工具需调用 `omo_rules action=path` 等显式查询。工具注入不等于通用只读权限：除受明确配置/守卫约束的入口外，不承诺任意 agent 或工具具备普遍只读能力。
- `omo_handoff` 不会自动采集 docs/notes 正文；交接可附 compiled rules 快照（若存在），并在快照缺失时提供根 AGENTS/CLAUDE 导航正文，但不保证完整收集规则或 docs/notes；接收者仍应按导航显式读取所需规则源。
